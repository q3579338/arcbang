# 高维宇宙的「可看之物」v1（2026-09-17 用户拍板）

用户原话：「高维要有自己的『可看之物』，而不是 3 维的残影」。

背景：随机引爆的宇宙里 D≥4 占约 55%，D=3 只占 3.5%。现在 D≥4 的体验是
「混沌遮罩 → 3 维 PM 粒子网的投影（按牛顿力外推，标了外推）→ 恒星系层的轨道投影演示 → 到头」。
诚实，但薄；而且那张粒子网**不是高维数据**，是 3 维模拟换了个力律。

本规格加两样真正属于高维的东西。铁律不变：**不许把示意写成计算**——投影必须是真投影，悬崖必须是真积分。

---

## 一、真·D 维 N 体 + 可换轴的投影（主功能）

### 物理
- 在 **D 维**空间里做直接求和 N 体（不是 PM，格点在 D 维下爆炸）。力律 F ∝ r^{−(D−1)}，
  软化长度与「核以最大尺度归一」沿用 `ui/planets.js` 轨道演示的同一套口径（同一个 D 下两处数值一致）。
- 初态：D 维盒子里的近均匀分布 + 小随机速度 + 弱密度扰动（用区块哈希派生的 rng，同一哈希同一初态）；
  背景膨胀用引擎已算好的 a(t)（共动坐标 + Hubble 阻尼），与 3 维 PM 的做法对齐。
- 积分：leapfrog（KDK），步长自适应但**子步数有硬上限**，超预算本帧到此为止（照 `stepThreeBody` 的先例）。
- 粒子数按设备自适应：WebGPU 直接求和 N=16k–32k；WebGL2/CPU（Worker）N=1k–3k。
  D 越高每粒子内存越大（D 个坐标 + D 个速度），N 上限按 D 缩。
- **预期结果就是「不成团」**：D≥4 时 r^{−(D−1)} 没有束缚态，粒子要么互相飞散要么两两坠核。
  这正是要给玩家看的物理事实，不要为了好看去修它。

### 投影
- 渲染时把 D 维位置投到玩家选定的 3 根轴 (x_i, x_j, x_k)，其余维度作为颜色/亮度（例如第 4 根轴映射色相、剩余维度的范数映射亮度），
  HUD 明示：「投影 (x₃, x₇, x₁₂) · 其余 11 维折进颜色」。
- 操作：`P` 或按钮「换一个投影角度」随机换一组轴；面板里也能手选三根轴；`[` `]` 在预设序列里前后翻。
- 同一份数据换轴后画面整个重排——这是「同一个宇宙无限多张脸」，3 维宇宙没有的玩法，首页和 HUD 文案要点明。
- 可选：切片模式（把未选轴限制在 |x|<ε 的薄片内只画这一片），标注「切片 · 厚度 ε」。

### 也覆盖 D≤2（2026-09-17 用户追加）
- 同一套 D 维 N 体同样用于 **D=1 / 1.5 / 2**：那里 r^{−(D−1)} 是常力（D=1）或 1/r 对数势（D=2），
  引擎说「没有牛顿吸引，物质无法聚集」——真算出来的画面自然不成团，正好替换掉现在那张
  「照样结团、只加了标注」的 3 维 PM 外推网（审计报告第 5 条）。约 20% 的宇宙观感会变，这是有意的。
- D=2 的镜像（二维世界模式）保留；D=1/1.5 没有镜像可进，HUD 说明为什么（一维/分数维下没有可进入的结构）。

### 原著场景优先（2026-09-17 用户追加：「原著在分数维下的描写要恢复」）
- `ui/scenes.js` 按《镜子》第八章做的场景优先级高于 N 体：
  - 2 ≤ D < 3（D=2、2.5）→ **黑平面 + 垂直银线**（原著宇宙#4「二点五维」的原文描写）是主画面；N 体只作开关/底层，默认关。
  - D ≥ 4 → 先「混乱的色彩和形状」遮罩（原著六维宇宙），揭开后才是 N 体投影。
  - 'black'（宇宙#1 近空宇宙：极少粒子、全黑）与 'ocean'（宇宙#2 液体大洋：银色大膜 + 多彩露珠）目前按结局路由永远走不到，要恢复——见第五节。

### 接入
- 位置：**D<2、3<D<4、D≥4** 揭开遮罩（D≥4）或引爆（D≤2）之后，**替换**现在那张 3 维 PM 外推粒子网（那张网可以留作「3 维外推对照」按钮，默认不显示）；2<D<4（2.5 / 3.5）也走 D 维 N 体（3.5 维用分数维力律，同一份代码）。
- 顶部说明改成：「D=14 的宇宙 · 真 14 维 N 体（N=…）· 投影到 (x₃,x₇,x₁₂)」，不再有「按牛顿力外推」那句——因为这次不是外推。
- 镜像的晕/星系层在 D≥4 下不再从 3 维网里找晕（那些晕是外推的假结构）；进入镜像直接落到恒星系层的轨道投影演示。
- 时间轴照常驱动 a(t)。

### 不做
- 不为 D≥4 生成行星/地表（引擎只为 D=3 生成）。
- 不改 engine/ 的物理判定（本功能只是可视化 + 独立的小 N 体）。

## 二、轨道演示：让玩家自己拨试探质点

- 在 D≠3 的轨道投影演示里加一个滑杆/拖拽：试探质点的初始半径 r₀ 从核内到核外连续可调（0.3–4）。
- 松手即从新初态重新积分，状态栏实时给：逃逸 / 坠核 / 核外近乎自由（F/F₁≈…）/ 核内尚未失稳，以及到那一刻的圈数。
- 目的：亲眼看 r^{−(D−1)} 在 r=1 处的悬崖——核外几乎无引力、核内一头栽进去，中间没有稳定带。
- D 在 (2,4) 时同一滑杆看到的是进动轨道（稳定不闭合）。
- 2.5 那档「几乎不受力」是软化把引力吃掉了（审计报告指出）：软化长度按 D 调，保证 D<4 时核外仍有像样的引力。

## 五、恢复原著的 black / ocean 场景（待定触发条件）

现状：`scenes.js` 的 `sceneFor()` 只在结局类型为 `LIQUID_OCEAN` 等旧类型时才给这两个场景，而现引擎的 12 种结局里没有这些类型，所以永远走不到。
恢复的难点不在画，在**触发条件必须诚实**：
- 'black'：可以按物理触发——物质密度极低、无结构（例如 HEAT_DEATH_NO_STRUCTURE 且 Ω_m 极小，或 NO_ATOMS 且粒子数极少），标注「近空宇宙 · 示意」。
- 'ocean'：原著里首长自己就质疑「400 亿光年深的海洋早坍缩成黑洞」，没有物理条件能推出它。只能作为**致敬原著的彩蛋**：由哈希派生的稀有触发（≈1%）+ 明确标注「原著第八章宇宙#2 · 文学场景，不是物理结论」。这条要用户拍板。

## 四、验收

- D=4 / 6 / 14 / 18 各截图：遮罩 → 揭开 → 换三次投影轴（画面明显不同）→ 进镜像到轨道演示 → 拨滑杆看到悬崖。
- 帧耗时：WebGPU 档 16k 粒子 ≤ 8 ms/帧；CPU 档 2k 粒子 ≤ 8 ms/帧（Worker 里算，主线程只画）。
- `engine/test.js`、`planet.test.js`、`check-dist.js` 全过；bnb/btc 产物除新增代码外行为不变（三站共用，这是修正不是站点差异）。
- 不许出现「成团 = 结构」的暗示：HUD 在 D≥4 下明写「没有束缚结构，这是 r^{−(D−1)} 的直接后果」。
